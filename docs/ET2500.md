# BNG eBPF di Asterfusion ET2500: kemampuan, hasil uji, dan roadmap

Diperbarui: 23 Oktober 2026 (versi sebelumnya: `/root/backup/RINGKASAN-BNG-ET2500.md.20261022`)
Perangkat: Asterfusion ET2500, Marvell OCTEON 10 CN102 (8 core Neoverse N2), 16 GB RAM, port 10G
Software: BNG eBPF berbasis `codelaboratoryltd/bng`, dikembangkan di fork **`najiebhaswell/bng`**, branch **`et2500-fixes`** (commit terakhir `f873359`)
OS: Debian 12, kernel vendor 6.6.46 dengan 6 patch driver `rvu_nicpf` (lihat Lampiran B)
Skrip lab dan tuning: `deploy/et2500/` di repo (di ET2500 terpasang di `/root`). Alamat RADIUS diset di `/etc/bng/lab.env` (`RADIUS_SERVERS=host:port`), tidak disimpan di git.

---

## 1. Ringkasan

ET2500 sekarang berfungsi sebagai BNG lengkap untuk pelanggan broadband. Semuanya sudah diuji end-to-end dengan BNG Blaster dan FreeRADIUS:

- **PPPoE dan IPoE (DHCP)**, dengan autentikasi, accounting, dan CoA lewat RADIUS
- **CGNAT** dengan port block per pelanggan dan log untuk keperluan hukum
- **Dual stack IPv6**: WAN /64 via SLAAC dan prefix delegation via DHCPv6
- **Rate limit per pelanggan**
- **Manajemen sesi** lewat CLI dan REST API

Trafik pelanggan diteruskan sepenuhnya di XDP/eBPF. Proses userspace hanya menangani control plane.

Hasil terukur:
- **10.000 sesi PPPoE** naik dalam ~50 detik.
- **5.000 sesi dual stack + CGNAT** pada **9,6 Gbps** tanpa loss.
- **Line rate 10G per arah untuk trafik IMIX** (rata-rata 618 byte) dengan CPU ~82%.

## 3. Hasil uji (BNG Blaster, lab ET2500)

| Uji | Hasil |
|---|---|
| Setup 10.000 sesi PPPoE (IPv6 aktif di BNG, klien IPv4 saja) | 10.000/10.000 dalam ~50 detik, laju stabil 200/detik (batas start-rate Blaster), 0 sesi terputus |
| 5.000 sesi PPPoE dual stack + CGNAT | 30.000/30.000 flow, **9,6 Gbps downstream / 1,9 Gbps upstream**, 0 loss, CPU ~64% |
| 2.000 sesi PPPoE dual stack + CGNAT (1400 byte) | 12.000 flow, 9,3–9,4 Gbps per arah, 0 loss |
| 2.000 sesi IPoE + CGNAT | 4.000 flow, 9,2 Gbps per arah, 0 loss |
| IMIX 618 byte (76/256/576/1024/1492), 1.000 sesi dual stack + CGNAT | **9,6 Gbps di kabel per arah (1,85 Mpps)**, loss ~0,01% (di luar BNG), CPU core paket ~82% |
| Overload (melebihi kapasitas) | Kelebihan trafik di-drop, perangkat tidak reboot, SSH tetap responsif |
| RADIUS | Auth, Accounting Start/Interim/Stop, CoA ganti kecepatan, Disconnect, Session/Idle-Timeout terverifikasi di FreeRADIUS |

### 3.1 Kapasitas

- **Batasnya di jumlah paket per detik, bukan Gbps.** Dengan semua fitur aktif, ET2500 meneruskan **1,85 Mpps per arah pada CPU ~82%** (7 core). Perkiraan batas CPU sekitar 2,2 Mpps per arah.
- **Dalam Gbps:**
  - trafik broadband biasa (paket besar dominan): line rate 10G per arah;
  - IMIX berat: line rate 10G per arah juga sudah tercapai;
  - paket kecil saja (64–128 byte): perkiraan sekitar 2 Mpps per arah (belum diuji terpisah).
- **Penghambat terbesar sebelumnya ada di platform, bukan di eBPF:**
  - SMMU/IOMMU mode strict memakan ~40% CPU paket;
  - interrupt coalescing default (1 µs / 10 frame).

  Keduanya sudah diatasi (lihat 4.3).

## 4. Operasional

### 4.1 Menjalankan (lab)

```
CGNAT=1 IPV6=1 bash /root/bng-lab-start.sh          # PPPoE + CGNAT + dual stack
CGNAT=1 IPOE_XDP=1 IPV6=1 bash /root/bng-lab-start.sh  # + IPoE di XDP
```

Sesudah reboot, BNG harus dinyalakan ulang dengan salah satu perintah di atas.

| File | Fungsi |
|---|---|

| `/root/et2500-lab-up.sh` | IOMMU identity untuk Ethernet12/13, VLAN 3001, IPv4/IPv6, forwarding |
| `/root/et2500-tune.sh` | RSS ke antrian 1–7, IRQ antrian i ke CPU i, coalescing 25 µs/64, IOMMU lazy bila belum identity |

| `/etc/bng/lab.env` | Alamat server RADIUS (`RADIUS_SERVERS`), tidak masuk git |
| `/var/log/bng/nat.log` | Log port block CGNAT (JSON) |

| Area | Flag |
|---|---|

| IPoE di XDP | `--ipoe-xdp` |

| Manajemen | `--api-addr --api-token-file` |

### 4.3 Tuning platform ET2500 (wajib untuk performa dan stabilitas)

1. **IOMMU identity untuk port data.** Setiap paket `XDP_REDIRECT` dipetakan DMA. Di mode strict, setiap unmap menunggu invalidasi TLB SMMU (~40% CPU). Alternatif permanen: bootarg `iommu.passthrough=1` via `fw_setenv`.
2. **CPU0 khusus housekeeping.** RSS hanya ke antrian 1–7, dan IRQ antrian i ke CPU i. Tanpa ini, overload membuat 8 core 100% di softirq, dan watchdog hardware CPLD (`tpk_wdt.service`) me-reset board tanpa log.
   - Jumlah antrian harus tetap 8, karena driver memilih antrian TX XDP berdasarkan nomor CPU.
   - Threaded NAPI tidak dipakai, karena biayanya 10–15% kapasitas.
3. **Coalescing 25 µs / 64 frame** (maksimum driver). Pembacaan status CQ lewat MMIO atomik per poll NAPI sempat memakan ~37% CPU.
4. **Ring RX 4096**, diset sebelum XDP attach.

### 4.4 Catatan produksi

- `rx-all on` hanya untuk lab: Blaster memakai UDP port 0. Jangan dipakai di produksi, karena frame dengan FCS error ikut diteruskan.
- Pakai `--log-level info`, bukan `debug`.
- Bila `--api-addr` tidak di loopback, wajib pakai `--api-token-file`.
- Mode IOMMU identity berarti NIC data tidak diisolasi IOMMU. Itu lazim untuk appliance (sama seperti setup DPDK).

## 5. Batasan saat ini

1. **State sesi hanya di memori.** Restart BNG membuat semua pelanggan reconnect; belum ada HA atau persistensi.
2. **Satu VLAN akses per instance, satu port akses dan satu uplink teruji.** LACP/bonding, QinQ, multi-VLAN, dan ECMP belum (lihat roadmap).
3. **Paket downstream lebih besar dari MRU di-drop tanpa ICMP Frag-Needed / Packet-Too-Big.** Belum ada TCP MSS clamping. RA sudah mengiklankan MTU 1492, jadi IPv6 TCP aman, tapi klien IPv4 bergantung pada MSS dari OS-nya sendiri.
4. **Trafik BNG ke pelanggan dan antar pelanggan PPPoE** (misalnya ping ke gateway) belum jalan. Jalurnya lewat kernel, yang tidak punya interface PPP.
5. **Batasan CGNAT:**
   - hairpin lewat router upstream, belum di dalam box;
   - belum ada ALG (FTP aktif, SIP, PPTP/GRE);
   - ICMP error dari pelanggan dan paket ber-IP options di-drop.
6. **IPoE:**
   - accounting belum membawa counter/interim dari XDP;
   - CoA dan Disconnect belum untuk IPoE (kill lewat CLI/API sudah bisa).
7. **Autentikasi RADIUS sinkron** di loop PPPoE (~1,6 ms per auth). Aman di 200 sesi/detik, tapi RADIUS yang lambat akan menahan control plane.
8. **Metrik Prometheus PPPoE dan CGNAT belum diisi.** Health check RADIUS di `pkg/resilience` memakai TCP, sehingga muncul warning palsu.
9. **Sesi IPv6-only** belum didukung.
10. **Server lama `--dhcpv6-enabled` / `--slaac-enabled` dan NAT44 TC** (mode tanpa XDP) belum diperbaiki dan tidak dipakai.
11. **Patch driver 4–6** belum diajukan ke Asterfusion; PR #19 hanya berisi patch 1–3.

### P1: kesiapan produksi

## Lampiran B: Patch driver octeontx2 (`rvu_nicpf`)

Driver ini built-in (`CONFIG_OCTEONTX2_PF=y`), jadi setiap fix butuh build ulang kernel dan reboot.

| # | Gejala | Penyebab |
|---|---|---|
| 1 | Balasan `XDP_TX` tidak pernah sampai | `iova` menunjuk ke awal headroom, bukan ke data paket |
| 2 | VLAN tag hilang lagi setelah XDP di-attach | `otx2_open()` selalu menyalakan lagi rx VLAN stripping |
| 3 | Program XDP bocor setiap attach/detach | `bpf_prog_add(rx_queues - 1)` tidak pernah dilepas |
| 4 | Hanya 1 paket per arah yang lolos (`rx_other_errs`, errcode 0x8) | Halaman `page_pool` di-unmap DMA-nya saat redirect, lalu dipakai lagi untuk RX |
| 5 | Buffer RX rusak berantai di bawah beban | `otx2_xdp_xmit` membebaskan frame sendiri **dan** melapor `n - drops` (double free saat SQ penuh) |
| 6 | `ethtool -G` saat ada trafik menyebabkan oops dan `rtnl_lock` macet | `otx2_cleanup_tx_cqes` menganggap `xdp_frame` sebagai `sk_buff` |

Image kernel:

| File | Isi |
|---|---|
| `/boot/Image` | Kernel #5, semua 6 patch (sedang dipakai) |
| `/boot/Image.vendor` | Kernel asli vendor (`/root/kernel/rollback-vendor-kernel.sh`) |
| `/root/kernel/Image.*` | Image antara (patch 1–3, 1–4, 1–5) |

Kalau gagal boot: di U-Boot jalankan `setenv bootargs ${bootargs2}; run bootmmc2`, lalu salin `Image.vendor` kembali ke p1.

Temuan driver lain yang belum di-patch: `otx2_xdp_xmit` memilih antrian TX dari `smp_processor_id()`. Kalau jumlah antrian dikurangi di bawah jumlah CPU, terjadi akses di luar array.

## Lampiran C: Temuan setup uji (bukan bug BNG)

- **BNG Blaster memakai UDP port 0** untuk session traffic. NIC menganggapnya error parse dan membuangnya sebelum XDP. Di lab diatasi dengan `ethtool -K <port> rx-all on`.
- **Blaster harus di-pin ke CPU** (`sudo pin-blaster.sh` ~3 detik setelah start). Tanpa itu, Blaster sendiri yang membuang paket pada beban tinggi.
- **Blaster tidak punya ukuran paket acak.** IMIX dibuat dari beberapa stream berbeda ukuran. Profil: `/etc/bngblaster/et-pppoe-ds-cgnat-1k-imix-{4,7,9}g.json`.
- **Stream IPv4 di belakang CGNAT harus dua arah dengan `"nat": true`.** Blaster mempelajari translasi dari arah upstream.
- **Paket pertama ke neighbor yang ARP-nya kedaluwarsa** sempat hilang (antrian ARP kernel). Ini artefak lab, karena Blaster diam di antara run.
- **`apt autoremove --purge docker-*` ikut menghapus `iptables`.** Skrip lab sekarang melewati iptables bila tidak ada; tanpa Docker, policy FORWARD default sudah ACCEPT.
